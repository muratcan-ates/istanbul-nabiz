**What it does today (four journeys, all verified against live data):**

1. *"Taksim'e 20 dakikaya varıyorum, hangi otoparkta yer var, ücreti ne?"* → live free spaces, tariff, distance, data age
2. *"500T 4. Levent'e ne zaman gelir?"* → arrival estimate with the method that produced it (stop sequence / distance / schedule)
3. *"M4'te arıza var mı? Kartal'da asansör var mı?"* → live disruption notices, lift/escalator/WC per station
4. *"Beşiktaş'ta koşu için hava nasıl?"* → PM10, AQI band, cleanest upcoming window

**Why it is more than an API wrapper:** it protects the upstream (one shared rate-limited client), it keeps the
history İBB does not publish (parking occupancy, bus positions), and it never states a number that is not in a
tool result.

## 1. Hard rules (non-negotiable, apply to every chat and every AI)

### 1.1 Git and authorship
- **No AI attribution anywhere.** No `Co-Authored-By`, no "generated by", no assistant names in commit messages,
  PR descriptions, code comments, README or docs. The author is Muratcan Ateş, full stop.
- Commit author: `Muratcan Ateş <muratcn.ates@gmail.com>`. Messages in English, imperative mood, explain **why**
  in the body when the change is not obvious. One logical change per commit.
- Feature work happens on `feat/<name>` branches. **Only the Integrator merges to `main`.** Nobody force-pushes.
- Never commit: secrets, `.env`, subscription/tenant IDs, keys, `data/lake/`, `data/reference/gtfs/`, `logs/`,
  `.venv/`. The repo is public.

### 1.2 Where the project lives
- Clone in `~/code/`. Never in a folder that iCloud, Dropbox or OneDrive syncs — file watchers corrupt `.git`
  and leak drafts.
- Python **3.12** via `uv venv -p 3.12 .venv`; system Python 3.14 is not used. PyPI is slow from this machine:
  `UV_HTTP_TIMEOUT=180 uv pip install --python .venv/bin/python <pkg>`.

### 1.3 Data, privacy, licence
- Data source: İBB Açık Veri Portalı, **İBB Açık Veri Lisansı (CC BY 4.0-based)**. Attribution line in README,
  UI footer, MCP server description: *"Kamu sektörü bilgilerini içerir — İBB Açık Veri Portalı, İBB Açık Veri
  Lisansı (CC BY 4.0)."*
- **Bus number plates are dropped at the parsing boundary and never stored or returned.** Vehicles are identified
  by door number only. Any change that reintroduces `Plaka` is rejected.
- **No personal data is stored server-side.** Any feature involving a user's location, profile or history must be
  designed *privacy-first*: on-device state, explicit opt-in, data minimisation, no server logs of location.
  KVKK (Turkish data protection law) applies; treat it as a hard design constraint, not a footnote.
- Outputs carry disclaimers: bus ETAs are estimates; air-quality output is not health advice.

### 1.4 Respecting İBB's gateway (this is the architecture, not a courtesy)
- `api.ibb.gov.tr` returns **HTTP 503 for every service** after ~15 rapid requests. The shared `PoliteClient`
  holds **≥ 6 s between calls per host**; the İETT budget is **80/hour** against a documented limit of 100.
- N users → at most 1 upstream call per cache window (single-flight TTL cache). Never add a code path that
  calls İBB per user request. Never bypass the client.
- The traffic endpoint returns XML unless `Accept: application/json` is sent.

### 1.5 Honesty of numbers
- Every tool result carries provenance (`source_url`, `reported_at`, data age). The agent says the age out loud.
- **Never fabricate a metric.** If it cannot be measured, write `n/a (reason)`. README placeholders `[T] [S] [E]`
  are filled only from `eval/results/`.
- The eval harness is the arbiter. A feature without a scenario in `eval/journeys.jsonl` is not done.

### 1.6 Technical constraints that shape every decision
- **Azure for Students** (~$100, no card): a hidden allowed-regions policy, ~4 vCPU, **Azure OpenAI quota may be
  zero**. GitHub Models was **retired on 2026-07-30**. Therefore the LLM is swappable by env (`NABIZ_LLM_*`),
  the agent has a **deterministic no-LLM mode**, and nothing on the critical path depends on OpenAI quota.
- Do not provision: Azure AI Search Basic (≈ $2.4/day idle), Stream Analytics, Data Factory data flows,
  Marketplace items. Do use: Storage, Functions Flex, Container Apps at `minReplicas 0`, App Insights,
  optional Azure Maps Gen2.
- MCP SDK is **2.x** (`MCPServer`, not `FastMCP`). The tool decorator must keep `functools.wraps` or every tool
  advertises `(*args, **kwargs)` and every call is rejected.
- Azure Data Explorer free cluster: no ARM, no cluster MI; the *caller's* MI is granted via
  `.add database nabiz ingestors ('aadapp=<clientId>;<tenantId>')`. Untested from this subscription — a gate.
- Tools are **parametric**. No free-form SQL/KQL from the model. Ever.

## 5. Multi-chat protocol

One **Integrator** chat owns `main`. Any number of **Feature** chats each own one branch and one file set.
**Research** chats (deep-research AIs) produce reports, not code.

### 5.1 Roles
| Role | Owns | May | Must not |
|---|---|---|---|
| Integrator (main chat) | `main`, `docs/NABIZ.md`, `DECISIONS.md`, `README.md`, `eval/journeys.jsonl` | merge, resolve conflicts, run full suite, cut scope | write feature code beyond glue |
| Feature chat `feat/<name>` | the files in its brief only | add tests, add a scenario to a *proposed* `eval/journeys.<name>.jsonl`, edit `docs/<name>.md` | touch `main`, other chats' files, `src/ibb_mcp/models.py` or `http.py` without a note to the Integrator |
| Research chat | nothing in the repo | return a report in the format of `docs/research_prompt.md` | invent APIs, prices or repos; every claim needs a URL and a date |

### 5.2 Opening a feature chat (paste in this order)
1. `docs/NABIZ.md` (this file)
2. The relevant research digest (from the Integrator)
3. The brief:

```
BRIEF · feat/<name>
Goal (one sentence):
Customer outcome it moves:
Timebox: <N> hours, hard stop at <time>. Ship the smallest slice that passes its scenario.
Files you own:
Files you may read but not edit:
Definition of done:
  - scenario(s) in eval/journeys.<name>.jsonl pass in deterministic mode
  - make lint test green; new tests for new code
  - no new upstream call path outside PoliteClient; no personal data stored
  - handoff report (5.3) posted
Out of scope:
```

### 5.3 Handoff report (feature chat → Integrator; exact format)
```
HANDOFF · feat/<name> · <commit sha>
What changed: (3–6 bullets, why not just what)
Files: (list)
Verified by: (real command output, pasted)
Scenario results: (table)
Upstream calls added: (none | list with cadence and cache TTL)
Privacy check: (what user data touched; where it lives; how it is deleted)
Risks / not done: (honest)
Reproduce: (commands)
```

### 5.4 Integration cadence (one-day sprint)
- Every 2 hours the Integrator pulls all `feat/*`, runs `make lint test`, runs `eval/run_eval.py --offline`,
  merges what is green, and updates §3 of this file.
- **Feature freeze at T-3h.** After that only fixes, docs, video.
- Scope cuts are the Integrator's call and are recorded in `DECISIONS.md`.

### 5.5 AI-SDLC loop (what "engineering excellence" means here)
`spec (brief) → build → tests → scenario eval → adversarial review → handoff → integrate → measure`.
Every step leaves an artefact in the repo. A change nobody can reproduce from the repo did not happen.

CI: GitHub Actions runs lint, tests and an offline MCP smoke test on every push. Deployment is `azd` from a
laptop until OIDC to the university tenant is verified; do not add deploy secrets to CI.
